매장 목록 불러오는 중…

📖 규칙 가이드

  1. 화면 구성위에서부터 ① 매장별 판매(날짜별 막대 차트) ② 업체별 판매 비율(도넛 2개) ③ 상품 검색. 상단 버튼: ↻ 새로고침 · 📖 규칙 가이드 · 🌙/☀️ 화면 모드. 데이터는 모두 Firebase 에 저장되고 열 때마다 불러옵니다.
  2. 상품 기준 (UPC MANAGER)상품은 전부 UPC MANAGER 에 등록된 것만 인정합니다. 가져오는 값: UPC · 영문명 · 한글명 · VENDER · ITEM CODE. UPC 는 숫자만 남기고 맨 앞의 0 을 모두 제거해서 비교합니다 (008801007021348 = 8801007021348, 중간 0 은 유지). 같은 UPC 가 여러 행이면 1개 상품으로 봅니다. UPC MANAGER 에 없는 UPC 는 차트·비율에서 제외됩니다(검색하면 "UPC MANAGER 미등록"으로 표시). 상품 목록은 UPC MANAGER 저장 시각이 바뀌면 자동으로 다시 받고, ↻ 새로고침은 즉시 다시 받습니다.
  3. 업체(VENDER) 기준업체 = UPC MANAGER 의 VENDER 값(= 중간 카테고리 축약어). 같은 UPC 가 여러 행이면 VENDER 가 들어 있는 첫 행의 값. 색: STI-WA 녹색 · JFC 노란색 · WIC 오렌지색, 그 외 업체는 자동 색. 표시 순서는 STI-WA → JFC → WIC → 나머지 이름순.
  4. 매장EGMM > SYSTEM > STORE 에 등록된 매장을 순서(order)대로 보여줍니다. 판매 데이터는 매장마다 따로 저장·표시됩니다.
  5. 업로드 파일POS 리포트 GROUP/상품별 일단위 판매현황(prsalesitemperdate.xls) 원본 그대로 사용. 시트가 여러 개(Sheet1, Sheet2 …)면 전부 이어서 하나로 읽습니다. ⬆ 매장별 판매 데이터 업로드 팝업에서 매장 카드에 파일을 끌어다 놓거나 클릭해서 선택. 날짜 선택 없음 — 날짜는 파일 안 C열에서 읽습니다. .xls · .xlsx · .csv 가능.
  6. 열 읽기 규칙A열 = UPC · C열 = 날짜 · D열 = 그날 판매 금액 (B열 상품명은 쓰지 않음). A열이 비어 있는 행은 바로 위에서 마지막으로 나온 UPC 의 다른 날짜 판매로 읽습니다(시트가 바뀌어도 이어받음). A열에 값이 있는데 7자리 이상 숫자가 아니면(상품별 소계 · 계 · 총계 · Page · 금액 등) 그 줄은 건너뛰고 이어받기도 끊습니다. A열 UPC 는 2번 규칙대로 앞 0 제거.
    A (UPC)C (날짜)D (금액)읽는 방법
    0088010070213482026-09-014.99새 상품 시작 → UPC 8801007021348
    2026-09-029.98A 비어 있음 → 위 UPC 의 9/2 판매
    2026-09-0314.97A 비어 있음 → 위 UPC 의 9/3 판매
    상품별 소계29.94UPC 아님 → 건너뜀, 이어받기 끊음
    0111528879992026-09-012.99다음 상품 시작
  7. 날짜 읽기C열은 엑셀 날짜 일련번호(예: 46266) 또는 2026-09-01 / 2026.09.01 / 2026/09/01 형식을 인정해 YYYY-MM-DD 로 바꿉니다. 날짜를 읽을 수 없는 행은 건너뜁니다.
  8. 판매가(단가)한 UPC 의 날짜별 금액(D열) 중 가장 낮은 금액 = 판매가. (하루에 1개만 팔린 날의 금액이 단가가 됨.) 예) 4.99 · 9.98 · 14.97 → 판매가 4.99.
  9. 수량날짜별 수량 = 그날 금액 ÷ 판매가, 나누어떨어지지 않으면 반올림(최소 1). 금액이 0 이거나 마이너스(반품·취소)인 행은 수량에 넣지 않습니다. 같은 UPC·같은 날짜가 두 줄 이상이면 수량을 합칩니다.
    날짜금액계산수량
    09-014.994.99 ÷ 4.991
    09-029.989.98 ÷ 4.992
    09-0314.9714.97 ÷ 4.993
    09-0412.0012.00 ÷ 4.99 = 2.4 → 반올림2
  10. 업로드 확인 팝업파일을 읽은 뒤 저장 전에 확인합니다: 매장 · 기간(첫 날짜 ~ 마지막 날짜, 일수) · 시트 수 · 상품 수(UPC 종류) · 판매 개수 · 읽은 행 수 · UPC 아님 행 수 · 0/마이너스 제외 수 · 단가 불일치(반올림) 수 · 파일 이름. "업로드"를 눌러야 저장됩니다.
  11. 저장 형식정리 결과는 UPC · 판매가 · 날짜 · 수량 4가지만 남깁니다. Firebase 경로 DATA / ITEM-ANALYZE / SALES / {매장}_{YYYY-MM}_{번호} — 매장·월 단위로 압축(gzip)해서 저장하고 한 달 데이터가 크면 여러 번호로 나눕니다. 한 줄 = "UPC[탭]일[탭]수량[탭]판매가".
  12. 쌓기 규칙업로드는 덮어쓰기가 아니라 쌓기입니다. 파일에 들어 있는 날짜는 그 날짜 전체가 새 값으로 바뀌고, 파일에 없는 날짜는 그대로 유지됩니다. 예) 9/1~9/29 를 올린 뒤 10월 파일을 올리면 9월은 그대로 두고 10월이 추가. 9월 파일을 다시 올리면 9월 날짜만 바뀌고 10월은 유지. 다른 매장 데이터에는 영향 없음.
  13. 날짜 삭제업로드 팝업의 매장 카드에 날짜별(품목 수 · 판매 개수) 목록이 있고, ✕ 를 누르면 확인 후 그 매장의 그 날짜만 삭제됩니다.
  14. 매장별 판매 차트 — 모양가로 4매장씩(창이 좁으면 2 → 1). 매장마다 날짜별 세로 막대, 막대 안을 업체 색으로 나눠 쌓고 조각마다 %, 막대 위에 합계. 한 번에 5일, ◀ ▶ 로 5일씩 이동, 기본은 가장 최근 5일. 막대 높이는 모두 같고 % 숫자가 보이도록 조각 최소 높이를 보장합니다. 판매 데이터가 없는 매장은 "판매 데이터 없음".
  15. 매장별 판매 차트 — 판매된 아이템 기준그날 그 매장에서 팔린 전체 판매 수량(같은 상품 여러 번 포함) 중 업체별 수량 비율. 막대 위 숫자 = 그날 총 판매 수량(개). 예) 그날 656개 중 STI-WA 475 · JFC 112 · WIC 69 → 72% · 17% · 11%.
  16. 매장별 판매 차트 — 등록된 아이템 기준업체별 등록 상품 수(UPC 중복 제외) 중 그날 팔린 상품 종류 수(같은 상품 여러 개 팔려도 1개) 비율. 조각 크기 = 업체별 등록 수, 조각 안 진한 부분 = 그날 팔린 상품, 연한 부분 = 안 팔린 상품, 조각 % = 그 업체 등록 대비, 막대 위 숫자 = 전체 등록 대비 %.
  17. 업체별 판매 비율 — 범위날짜와 상관없이 저장된 모든 날짜를 합쳐서 계산합니다. "전체 매장 보기" = 모든 매장 합산, "매장별 각각 보기" = 매장마다 따로(가로 2매장씩). 도넛 2개가 항상 같이 표시되고 각 도넛 위에 기준 이름, 오른쪽에 업체별 수치.
  18. 업체별 판매 비율 — 판매된 아이템 기준 (도넛)30일 동안 팔린 전체 판매 수량(같은 상품 여러 번 포함) 중 업체별로 몇 개 팔렸는지 %. 도넛 가운데 = 총 판매 수량. 합계 100%.
    업체판매 수량판매된 아이템 기준
    STI-WA5050 ÷ 100 = 50%
    JFC3030 ÷ 100 = 30%
    WIC2020 ÷ 100 = 20%
    전체100100%
  19. 업체별 판매 비율 — 등록된 아이템 기준 (도넛)① 업체별 등록 상품 수 = UPC MANAGER 등록 UPC 수, 같은 UPC 가 여러 행이면 1개만. ② 판매된 상품 수 = 업로드된 판매 리스트에서 팔린 UPC 종류 수, 30일 동안 여러 개 팔려도 1개. → 업체마다 등록 상품 중 몇 % 가 팔렸나. 도넛 조각 크기 = 업체별 등록 수, 조각 안 진한 부분 = 판매된 상품, 연한 부분 = 안 팔린 상품, 조각 % = 그 업체 등록 대비, 가운데 = 전체 등록 대비 판매 %.
    업체등록 상품판매된 상품 (종류)등록된 아이템 기준
    STI-WA1,000400400 ÷ 1,000 = 40%
    JFC500150150 ÷ 500 = 30%
    WIC2005050 ÷ 200 = 25%
    전체1,700600600 ÷ 1,700 = 35.3% (가운데)
  20. 상품 검색검색창에 UPC 또는 상품명, Enter 또는 검색 버튼. 숫자만 넣으면 UPC 검색(앞 0 무시 — 8801007021348 · 08801007021348 같은 상품), 글자가 있으면 영문명·한글명에서 찾되 빈칸은 전부 무시(신라면5입 = 신라면 5입). 결과: UPC · 영문명 · 한글명 · 판매가(매장별 단가 중 가장 낮은 값) · 업체, 그 아래 날짜 × 매장 수량표(최근 날짜부터, 맨 아래 합계, 판매 없는 날짜는 생략). 결과는 5개까지 보이고 나머지는 스크롤, 최대 30개.
  21. 화면 · 글씨 · 모드창 너비에 맞춰 늘어나고(고정 폭 없음) 글씨는 최소 10px. 🌙 NIGHT / ☀️ DAY 는 EGMM · PLU/UPC MANAGER 와 같은 설정을 공유해 함께 바뀝니다.
